# Leave Sync Implementation

วันที่ดำเนินการ: 15 ตุลาคม 2026

## สรุปการดำเนินการ

- เพิ่มการเชื่อมต่อ Firebase โปรเจกต์ลาแยกจาก Firebase ของแอพหลัก
- อ่านข้อมูลจาก Collection รูปแบบ `leave_requests_20XX`
- อ่าน `users` ของโปรเจกต์ลาเพื่อจับคู่ `user_id` กับ `employee_id` ก่อนบันทึก
- ใช้ Anonymous Authentication และอ่านข้อมูลแบบ Read-only เท่านั้น
- เพิ่มปุ่ม `Sync Leave Data` ในหน้า Admin → Discipline
- ไม่อ่านข้อมูลลาอัตโนมัติเมื่อเปิดหน้า เพื่อลดจำนวน Firebase Reads
- Mapping รหัสพนักงานจากส่วนก่อน `_` ของ Document ID กับ `staffCode` ในแอพ
- นำข้อมูลประเภทลาที่อนุมัติแล้วไปเติมใน Discipline รายไตรมาส/รายเดือน
- บันทึกข้อมูล Sync Ledger และ Discipline ที่ Sync แล้วใน Firebase ของแอพหลัก
- แสดงจำนวนวันที่ใช้จริงของลาป่วย/ลากิจ/ลาพักร้อนแยกตาม Q1–Q4 ใน Part 2 Modal แบบ Readonly
- เก็บ `Last Sync`, Collection ต้นทาง, `sourceDocId`, สถานะ และเวลาแก้ไขต้นทาง

## การป้องกันข้อมูลซ้ำ

ใช้คีย์ถาวรจาก:

```text
sourceCollection::sourceDocId
```

การกด Sync ซ้ำจะทำงานแบบ Upsert:

- เอกสารเดิมและข้อมูลไม่เปลี่ยน: `unchanged`
- เอกสารเดิมแต่ข้อมูลเปลี่ยน: `updated`
- เอกสารใหม่: `added`
- ไม่พบพนักงานในแอพ: `unmatched`
- เอกสารหายจากการ Full Sync: `missing`

จะไม่สร้างรายการ Discipline ซ้ำสำหรับพนักงาน/ปี/ไตรมาสเดิม

## โครงสร้างข้อมูลในแอพหลัก

ข้อมูลต้นทางที่อ่านแล้วจะถูกเก็บในฟิลด์ `leaveSyncRecords` ของเอกสารข้อมูลแอพหลัก และข้อมูลสรุปการ Sync จะเก็บใน `leaveSyncMeta` โดยข้อมูลคะแนนยังคงอยู่ใน `quarterlyEvaluations` ของ `part: "part2"` ตามโครงสร้างเดิม

ฟิลด์ที่นำเข้าจากการลา:

- `sick` → ลาป่วย
- `personal` → ลากิจ/ธุระส่วนตัว
- `vacation` → ลาพักร้อน/ลาประจำปี

ใน Modal จะแสดงจำนวนวันที่ลาอนุมัติแยกตาม Q1–Q4 โดยไม่อ่านหรือแสดงข้อมูลโควต้า

การกระจาย Quarter ใช้วันที่ลา (`start_date`/`end_date` หรือวันที่จาก Attendance) และจำนวนวันจากรายการลาอนุมัติ แล้วบันทึกผลลง `quarterlyEvaluations` ของแต่ละ Quarter พร้อมเก็บต้นฉบับไว้ใน `leaveSyncRecords`

เมื่อ Full Sync แล้วไม่พบรายการลาที่อนุมัติของพนักงาน ระบบจะใส่ค่า leave เป็น `0` ในทุกเดือนของปีนั้น ทำให้ Discipline แสดงคะแนนเต็ม 20 คะแนนในกรณีไม่มีข้อมูลขาด/ลา โดยยังคงข้อมูล `warning` หรือค่าที่ HR กรอกเองไว้

แม้ยังไม่ได้กด Sync หรือช่องของเดือนยังว่างอยู่ หากไม่มีข้อมูลขาดงาน/ลา/ใบเตือน ระบบจะถือเป็นเดือนปกติและคำนวณเป็น `20/20` โดยไม่ต้องกรอกเลข `0` เอง

ฟิลด์ `absent`, `warning`, `note` และโควต้าที่ใช้คำนวณคะแนนยังคงเป็นข้อมูลที่ HR จัดการในแอพ

## การลดจำนวน Reads

- ทุกครั้งที่กดปุ่ม `Sync Leave Data` ระบบจะอ่าน Collection ของปีนั้นแบบ Full Sync
- Full Sync จะประมวลผลพนักงานทุกคนที่แสดงในหน้า Discipline แม้ไม่มีเอกสารลาใน Firebase ต้นทาง
- การกด Sync เป็นการกระทำด้วยตนเองเท่านั้น จึงไม่มีการอ่านอัตโนมัติเมื่อเปิดหน้า

หมายเหตุ: การไม่บันทึกข้อมูลซ้ำทำได้จาก `sourceDocId` และ fingerprint ของเอกสาร แต่ Full Sync จะอ่านเอกสารต้นทางซ้ำทุกครั้งตามคำขอให้อัปเดตพนักงานทุกคน จึงมีค่า Read ตามจำนวนเอกสารใน Collection ต่อการกด Sync

## เงื่อนไขฝั่ง Firebase โปรเจกต์ลา

ระบบจะพยายามใช้ Anonymous Authentication ก่อน หากโปรเจกต์ยังไม่ได้เปิด Anonymous Auth แต่ Firestore อนุญาต Public Read ระบบจะอ่านต่อได้โดยไม่ต้อง Login เพื่อรองรับการตั้งค่าปัจจุบัน

การตั้งค่าที่แนะนำคือเปิด Anonymous Authentication และตั้ง Firestore Rules ให้ผู้ใช้ Anonymous อ่านได้ แต่ไม่อนุญาตให้เขียน เช่น:

```text
allow read: if request.auth != null;
allow write: if false;
```

หากต้องการใช้ Public Read โดยไม่เปิด Anonymous Authentication ให้ใช้กฎแบบ Read-only แทนกฎในภาพที่เป็น `allow read, write: if true;`:

```text
allow read: if true;
allow write: if false;
```

กฎ `allow read, write: if true;` เปิดให้บุคคลทั่วไปแก้ไขหรือลบข้อมูลได้ จึงไม่ควรใช้กับข้อมูลจริง

ระบบจะไม่เขียนสถานะกลับไปยัง Firebase โปรเจกต์ลา สถานะ Sync ทั้งหมดจะถูกบันทึกใน Firebase ของแอพหลักเท่านั้น

## การตั้งค่าเงื่อนไขหักคะแนน Discipline

- เพิ่มปุ่ม `ตั้งค่าหักคะแนน` ในหน้า Admin → Discipline สำหรับผู้มีสิทธิ์กรอกวินัย
- เปิด Modal แล้วกด `เพิ่มเงื่อนไข` เพื่อเพิ่มรายการประเภทวินัย, ค่าที่มากกว่า และคะแนนที่ต้องหัก เช่น `ลาป่วย มากกว่า 3 วัน = -1 คะแนน`
- สำหรับ `ลาพักร้อน` ระบบใช้ค่าจำนวนวันที่เกินโควต้าพักร้อนของพนักงานเป็นตัวเปรียบเทียบ
- กฎของแต่ละประเภทจะเลือกกฎที่ตรงกับค่าสูงสุดเพียงรายการเดียว แล้วนำผลของแต่ละประเภทมารวมกัน ไม่หักรายการซ้ำภายในประเภทเดียวกัน
- กฎถูกเก็บแยกตามปีในฟิลด์ `disciplineRulesByYear` ของข้อมูลแอพหลัก
- เมื่อบันทึกกฎใหม่ ระบบจะคำนวณคะแนน `part2` ของปีนั้นใหม่ทันที และการ Sync ครั้งถัดไปจะใช้กฎเดียวกัน
- หากยังไม่เคยตั้งค่า ระบบใช้ค่าเริ่มต้นเดิม: ลาป่วย, ลากิจ, ลาพักร้อน, ขาดงาน และใบเตือน ตามเกณฑ์เดิมของหน้า Discipline

## การเปลี่ยนแปลงขั้นตอนอนุมัติวินัย

- ยกเลิกขั้นตอน `HRM (MD) อนุมัติ` สำหรับบันทึกวินัย
- หน้า Discipline ไม่แสดงสถานะรออนุมัติ, ปุ่มอนุมัติ หรือการล็อกข้อมูลจาก `hrmApproved` อีกต่อไป
- ใช้ผลจาก `Sync Leave Data` และการบันทึกของ HR เป็นข้อมูลวินัยที่ใช้งานโดยตรง
- ฟิลด์อนุมัติเดิมในข้อมูลเก่าจะไม่ถูกนำมาใช้กับหน้าจอใหม่ เพื่อรองรับข้อมูลย้อนหลังโดยไม่ต้องลบข้อมูลเดิม
